# 🧩 Macros & Preprocessor

Ivy provides full support for C/C++ style preprocessor macros and conditional compilation directives. Macros are expanded during the preprocessor phase before syntactic analysis.

---

### 1. Object-like Macros

Constants and symbolic values defined with `#define`:

```ivy
#define PI 3.14159
#define MAX_BUFFER_SIZE 1024
#define COMPANY_NAME "Acme Corp"
```

---

### 2. Function-like Macros

Parameterized macros that perform inline text replacement:

```ivy
#define SQUARE(x) ((x) * (x))
#define MAX(a, b) (((a) > (b)) ? (a) : (b))
```

---

### 3. Stringification (`#`) & Concatenation (`##`)

- **Stringification (`#`):** Converts a macro argument into a string literal.
- **Concatenation (`##`):** Glues two tokens together into a single token.

```ivy
// Stringification (#)
#define PRINT_VAR(x) io::print("{} = {}", #x, x)

// Concatenation (##)
#define DECLARE_VAR(type, name) type var_##name
```

---

### 4. Predefined Macros

Ivy provides standard built-in predefined macros for source inspection and environment querying:

| Macro | Description | Format / Value |
| :--- | :--- | :--- |
| `__LINE__` | Current line number in source code | Integer |
| `__FILE__` | Path of the current source file | String |
| `__DATE__` | Compilation date | `"MMM DD YYYY"` |
| `__TIME__` | Compilation time | `"hh:mm:ss"` |
| `__ivy__` | Version of the Ivy language standard in use | Integer (e.g. `202604L`) |
| `__cplusplus__` | C++ standard version set by the auxiliary backend | Integer |

---

### 5. Conditional Compilation

Control which sections of code get compiled based on macro definitions:

```ivy
#define FEATURE_ENABLED

#ifdef FEATURE_ENABLED
    // Compiled only if FEATURE_ENABLED is defined
#endif

#ifndef MY_HEADER_H
#define MY_HEADER_H
    // Traditional header guard
#endif

#if defined(DEBUG) && !defined(NDEBUG)
    // Complex conditional compilation
#elif defined(TESTING)
    // Alternative branch
#else
    // Default fallback
#endif
```

---

### 6. Pragmas

#### `#pragma once`
Prevents duplicate file inclusion without writing manual header guards:

```ivy
#pragma once

// File contents will only be included once per translation unit
```

#### `#pragma ivy cnumber`
Enables legacy C-style numeric types (`short`, `int`, `long`, `long long`, `unsigned`, `float`, `double`) within the current file or translation unit:

```ivy
#pragma ivy cnumber

int count = 10;
unsigned long total = 1000UL;
```

---

### 7. Macro Safety & Type-Safety Policy

In C++, preprocessor macros bypass type checking and scope boundaries, frequently leading to subtle bugs. In Ivy, preprocessor compatibility is preserved while strictly enforcing safety:

#### 1. Post-Expansion Verification
- Macro replacement occurs exclusively during the **Preprocessor** stage.
- Expanded tokens must pass through the full compilation pipeline: `Parser` $\to$ `HIR (Type Checker)` $\to$ `MIR (Borrow & Lifetime Checker)`.
- If expanded code causes a type mismatch or lifetime violation, `ivyc` emits an error at the exact call site and expansion location.

#### 2. No Safety Bypass
- Code generated by macros cannot bypass Ownership, Borrowing, or Lifetime checks.
- Any raw pointers or unsafe operations inside macro expansions still require an enclosing `unsafe { ... }` block.

#### 3. Modern Type-Safe Alternatives in Ivy

Ivy recommends replacing legacy macros with modern, type-safe language constructs:

| Use Case | Legacy C++ Macro | Modern C++/Ivy Type-Safe Alternative |
| :--- | :--- | :--- |
| **Constants** | `#define BUFFER_SIZE 1024` | `constexpr int32 BUFFER_SIZE = 1024;` |
| **Inline Logic** | `#define SQUARE(x) ((x) * (x))` | `inline fn square(auto x) { return x * x; }` |
| **Generic Logic** | `#define MAX(a, b) (((a) > (b)) ? (a) : (b))` | `template<typename T> T max(T a, T b) { return a > b ? a : b; }` |
| **Conditional Code** | `#ifdef ... #endif` inside function | `if constexpr (...) { ... }` |
